에이전트는 계획→실행→관찰→조정을 스스로 돈다

챗봇은 ②에서 멈춘다 — 에이전트는 ③에서 어긋나면 ④를 거쳐 ②로 되돌아간다

사람 개입 없이 "에러 나면 고치고 다시 실행"을 반복한다 — 이것이 8초 답변과 45분 자율 작업의 차이다
용어추론 루프 — ①~④를 목표 달성까지 반복하는 자율 순환. 이것이 "8초 답변"과 "45분 자율 작업"의 차이를 만든다
"에러 나면 스스로 고치고 다시 실행"이 체감 포인트. 사람의 역할은 검토자·결정권자로 올라간다.

명령어는 사람이 부르는 자동화, 훅은 조건이 부르는 자동화다

① 명령어 (Slash Command)

절차를 담은 md 한 장 = 새 명령어 하나 — 자주 쓰는 워크플로우의 단축키

/조사분석관 → 수집 → 정리 → 전년 대비 표 생성까지 한 줄

타이핑 몇 글자가 절차 전체를 부른다 — 팀원 누가 불러도 같은 결과

② 훅 (Hook)

파일 저장·명령 실행 전후에 자동 개입 — 사람이 잊어도 규칙은 지켜진다

예: 원본 데이터 수정 시도는 자동 차단
예: 산출물 저장 때마다 수치 표기 규칙 검사
예: 작업 기록을 로그로 자동 축적

검증을 의지가 아니라 구조에 맡기는 방법 — 훅의 예시가 전부 '검증 계열'인 것은 우연이 아니다
비교명령어 = 사람이 부르는 자동화 · 훅 = 조건이 부르는 자동화 — 함께 쓰면 "부르면 돌고, 잊어도 지켜지는" 체계가 된다
훅 예시가 모두 검증 계열인 것이 의도 — 오늘의 주선율(신뢰)을 부품 설명에서도 유지.

API는 '기계용 창구', MCP는 그 창구에 꽂는 '표준 플러그'

낯선 약어지만 하는 일은 단순하다 — AI에게 지금 이 순간의 원자료를 가져다주는 통로

사람은 눈으로 보고 옮겨 적는다 — API는 기계가 곧바로 받아 가는 창구같은 자료, 창구만 다르다

MCP — 창구에 꽂는 표준 플러그

제각각인 창구 규격을 AI 쪽에서 하나로 통일한 어댑터콘센트마다 다른 어댑터 → USB-C 하나로

내 질문"환경부 집행률 뽑아줘"
→
MCP표준 플러그로 연결규격 통일
→
API기관의 기계용 창구열린재정·국회·법제처
→
오늘자 원자료그 수치로 답한다
이 통로가 없으면 AI는 학습된 기억으로 답한다 — 철 지난 숫자의 출처 — 붙이면 오늘자 원자료로 답한다

설치 프롬프트 하나 — 붙여넣으면 앱이 저장소를 받아 온다

https://github.com/parkjui92/paper-proofread 저장소를 ~/.claude/skills/paper-proofread 폴더에 클론해줘.
  • 권한 창이 뜨면 허용 — 앱이 저장소를 받아 그 폴더에 넣는다 명령을 외울 일은 없다 · 무엇이 실행됐는지만 보면 된다
  • 확인 — 그 폴더에 SKILL.md가 생겼으면 설치 끝 이 파일이 4절에서 본 '절차서' 그 자체다
  • ~/.claude/skills/는 전역(글로벌) — 어느 폴더를 열어도 쓸 수 있다 프로젝트 폴더 안 .claude/skills/에 두면 그 폴더에서만 보인다 — 오늘은 전부 전역에 설치한다
  • 스킬은 대화를 시작할 때 읽힌다 — 설치 후 새 대화를 열어야 스킬로 인식된다
~/.claude/skills/ 아래에 폴더 하나가 생긴 것 — 그것이 설치의 전부다 · 지우면 삭제, 복사하면 공유, 전역이라 어디서나 호출
막히면"git을 찾을 수 없다"가 나오면 Windows Git 미설치 — 준비 ①로 · 클론이 끝났는데 스킬이 안 보이면 새 대화 열기 · 그래도 안 되면 앱 재시작
설치는 주소를 주고 말로 시킨다 — 명령 철자를 외우는 것이 지난 실습의 병목이었다. 대신 실행된 명령이 무엇이었는지 보여 준다. "새 대화를 열어야 인식된다"를 두 번 말한다.
2부 · 실습 ① — 실행

새 대화를 열고 — 틀린 문장 하나를 스킬로 교정해 본다

paper-proofread 스킬로 다음 문장을 교정교열해줘. 교정표(원문·수정·근거)도 같이 보여줘. 아버지가방에들어가시는지곰곰히생각해봤다. 이 정책은 향후 지속가능한 발전을 위해 검토되어질 필요성이 있다고 사료된다.
  • 확인 — 교정표에 띄어쓰기(아버지가 방에 들어가시는지) · 맞춤법(곰곰히→곰곰이) · 이중 피동(검토되어질→검토될) · 번역투(필요성이 있다고 사료된다)가 잡히면 성공
  • 스킬 없이 같은 문장을 넣어 보면 차이가 보인다 — 근거 열이 있고 없고
  • 파일로도 된다 — 원고를 대화창에 끌어다 놓거나, "다운로드 폴더의 ○○.docx 교정교열해줘"처럼 경로를 말하면 수정본과 교정표를 파일로 낸다 .docx · .hwp · .pdf · .md — 실무에서는 이쪽 · 오늘은 안내만
"AI에게 절차를 주면 그대로 일한다" — 프롬프트를 매번 길게 쓰지 않는다 · 이것이 실습②·③의 뼈대다
문장 하나로 1분 안에 끝내는 실습. 곰곰히·검토되어질·사료된다가 잡히는지 화면으로 확인시킨다. 파일 방식은 시연만 — 실무에서 원고 파일을 끌어다 놓으면 수정본·교정표가 파일로 나온다고 안내하고 넘어간다.

선택 ① 1단계 — 내 인증키 받기

법제처 국가법령정보 공동활용은 무료·즉시 — 가입 이메일의 @ 앞부분이 곧 인증값이다

  1. open.law.go.kr 접속 → 오른쪽 위 로그인 → 아래 사용자 가입(이메일)
  2. 상단 OPEN API → 왼쪽 OPEN API 신청 활용 목적 "업무 참고·학습용" · 사이트 URL "없음"으로 적어도 된다
  3. 승인 뒤 마이페이지 → API인증키관리에서 확인 OC 값 = 가입 이메일의 @ 앞부분 — 예: hong@korea.kr이면 hong
공용 시연키를 쓰지 않는다 — 남의 키로 성공하면 자기 키를 끝내 발급하지 않고 실무에서 같은 자리에 막힌다

출처: 법제처 국가법령정보 공동활용 — 회원가입 · OPEN API 신청

선택 ① 2단계 — 키는 파일에, 일은 말로

먼저 — 파일은 앱이 만들고, 값은 내가 직접 넣는다
이 폴더에 .env 파일을 만들고 LAW_OC= 까지만 적어줘. 값은 내가 직접 넣을 테니 비워 두고, 파일을 열어서 보여줘.
값을 넣은 뒤 — 주소는 내가 조립하지 않는다
이 폴더 .env의 LAW_OC 값을 읽어서, 법제처 국가법령정보 API로 "국가재정법"을 검색해줘. 법령명·법령ID·공포일자·시행일자·소관부처를 표로 정리하고, 네가 실제로 호출한 주소도 같이 보여줘.
  • 확인 — 표에 시행일자가 있고, 소관부처가 기획예산처·재정경제부로 나오면 오늘자를 받은 것 기획재정부로 나오면 원자료가 아니라 기억에서 답한 것이다
  • 대조 — 보여 준 주소를 브라우저에 붙여넣어 같은 값이 오는지 본다 이 한 번이 "가져왔다"와 "지어냈다"를 가른다
  • 채팅에 키 값을 붙여넣지 않는다 — 대화 기록·화면 공유·캡처에 그대로 남는다 · "값을 보여줘"도 하지 않는다

출처: 법제처 OPEN API 활용가이드 — 현행법령 목록 조회

.env는 점으로 시작해 탐색기에서 안 보일 수 있다 — 앱에 열어 달라고 하면 된다. 따옴표·공백 없이 LAW_OC=hong 한 줄. 소관부처로 오늘자 여부를 판별하는 대목이 이 장의 백미다.

주소를 주고 — 설치는 맡긴다
